# NeuroHunter

**NeuroHunter** — open-source проект для персонализированного поиска и анализа вакансий с учётом профессиональных навыков кандидата, его ограничений и предпочтений относительно рабочей среды.

Цель проекта — сделать поиск работы более персонализированным: оценивать не только соответствие кандидата требованиям работодателя, но и совместимость условий работы с потребностями самого кандидата.

**Статус:** активная разработка. Полноценный поисковый pipeline и механизм сопоставления вакансий с пользовательскими профилями ещё не завершены.

## Основная идея

NeuroHunter проектируется как система из нескольких этапов:

1. Получение и обработка данных о пользователе.
2. Формирование структурированного профиля кандидата.
3. Сбор вакансий из внешних источников.
4. Отбор вакансий по обязательным условиям.
5. Извлечение характеристик вакансий с помощью LLM.
6. Сопоставление вакансий с профилем пользователя.

## Python Analyzer

Python Analyzer — сервис на FastAPI, предназначенный для работы с пользовательскими данными и координации их обработки.

В проекте используются:

- FastAPI и Uvicorn;
- Pydantic для описания и валидации данных;
- SQLAlchemy и Alembic для работы с реляционными данными и миграциями;
- MongoDB для работы с документными данными;
- Celery для фоновых задач;
- библиотеки для обработки PDF и DOCX;
- интеграция с почтовыми сервисами и механизмами аутентификации.

Сервис содержит health-check, а также подключает API-маршруты приложения.

## Данные пользователя

Одна из основных задач проекта — представить сведения о кандидате в структурированном виде, пригодном для автоматической обработки.

### UserProfile

Исходный профиль пользователя содержит сведения о профессиональном опыте, навыках и условиях работы, которые пользователь рассматривает.

### UserFeatures

`UserFeatures` — структурированное представление профиля, предназначенное для дальнейшей обработки.

В модели предусмотрены следующие группы данных:

| Поле | Назначение |
|---|---|
| `job_titles` | Профессиональные направления и названия должностей |
| `hard_constraints` | Обязательные ограничения |
| `preferences` | Предпочтительные характеристики работы |
| `tolerances` | Допустимые, но не обязательно предпочтительные условия |
| `context` | Дополнительный контекст пользователя |

Разделение этих данных позволяет в дальнейшем отличать обязательные условия от предпочтений и более гибких критериев совместимости.

## Анализ резюме

Python Analyzer обрабатывает загруженные резюме и извлекает из них структурированные сведения с помощью LLM.

Результаты сохраняются в модели ResumeFeatures, которая содержит:

   - профессиональные направления и должности;
   - технические и гибкие навыки;
   - профессиональный опыт;
   - проекты;

   сильные стороны и ограничения, явно отражённые в резюме.

Структурированные данные используются в дальнейшем для сопоставления профессионального профиля кандидата с требованиями вакансий.

## Сбор и анализ вакансий

Go-компонент отвечает за сбор вакансий с Habr Career и их первичную фильтрацию по обязательным ограничениям пользователей (`hard_constraints`).

Текущий процесс включает:
- формирование поисковых запросов на основе `job_titles` пользователей;
- получение и дедупликацию вакансий;
- первичную фильтрацию по `hard_constraints`;
- сохранение подходящих вакансий в MongoDB;
- сохранение связей между вакансиями и пользователями в коллекции `vacancy_users`.

Python Analyzer отвечает за обработку пользовательских данных и дальнейший анализ вакансий.

В рамках анализа вакансий реализовано:
   - получение вакансий, ожидающих анализа;
   - извлечение характеристик вакансии с формированием VacancyFeatures;
   - извлечение требований вакансии с формированием VacancyRequirements;
   - сохранение результатов анализа в PostgreSQL;
   - использование Celery для выполнения фоновых задач анализа.

## Хранение данных

В проекте используются две базы данных с разными назначениями:

- **PostgreSQL** — реляционные и структурированные данные.
- **MongoDB** — документные данные.

Такое разделение позволяет развивать обработку пользовательских данных независимо от обработки исходных документов.

## Асинхронная обработка

Для выполнения фоновых задач используется связка Celery и RabbitMQ.

Она позволяет выносить длительные операции за пределы непосредственного HTTP-запроса и выполнять их асинхронно.
В настоящее время Celery используется для выполнения задач анализа резюме, пользовательских данных и вакансий.

## Оценка профессиональной совместимости

`ProfessionalFit` — компонент, предназначенный для оценки соответствия профессионального профиля кандидата требованиям конкретной вакансии.

В настоящее время реализуется математическая модель сопоставления навыков. Первоначальная версия включает:

- построение бинарной матрицы соответствия обязательных навыков вакансии навыкам из резюме;
- определение покрытия отдельных обязательных навыков;
- расчёт общего покрытия обязательных требований.

Дальнейшее развитие предполагает:

- нормализацию навыков и обработку альтернативных названий;
- учёт весов профессиональных требований;
- сопоставление предпочтительных навыков;
- оценку соответствия по опыту и образованию;
- формирование итоговой оценки профессиональной совместимости.

Результаты оценки предполагается сохранять для конкретной пары «резюме — вакансия».

## Запуск

Для запуска инфраструктуры необходимы Docker и Docker Compose.

1. Клонируйте репозиторий:

   ```bash
   git clone https://github.com/LeeGeller/neurohunter.git
   ```

2. Создайте файл конфигурации:

   ```bash
   cp .env.example .env
   ```

3. Заполните необходимые переменные окружения в `.env`. Одного копирования шаблона недостаточно: значения параметров подключения и секретов должны быть настроены.

4. Соберите и запустите сервисы:

   ```bash
   docker compose up --build
   ```

Команда запускает сервисы, описанные в `docker-compose.yml`. Для полноценной работы необходимо также корректно настроить подключения между компонентами и внешние зависимости, используемые приложением.

## Текущее состояние

NeuroHunter находится в стадии активной разработки.

Реализованы компоненты сбора и первичной фильтрации вакансий, обработка пользовательских данных, анализ резюме и извлечение характеристик вакансий с помощью LLM. Результаты анализа сохраняются в структурированном виде в PostgreSQL.

В настоящее время разрабатывается механизм оценки профессиональной совместимости кандидата с требованиями вакансии. Реализован первоначальный алгоритм сопоставления обязательных навыков на основе бинарной матрицы и расчёта покрытия.

Полный цикл персонализированного поиска и сопоставления вакансий пока не завершён.

**Ближайшие задачи:**

1. Разработать механизм нормализации и сопоставления навыков.
2. Продолжить разработку математической модели профессионального соответствия.
3. Реализовать сопоставление по предпочтительным навыкам, опыту и образованию.
4. Формировать и сохранять результаты сопоставления.

Дальнейшее развитие включает подключение новых источников вакансий, автоматизацию поиска, тестирование полного pipeline, подготовку production-инфраструктуры и создание пользовательского интерфейса.
